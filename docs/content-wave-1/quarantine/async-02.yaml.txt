    explanation: |
      Тело метода с модификатором `async` компилятор превращает в конечный автомат, и любое исключение внутри него,
      даже выброшенное до первого `await`, перехватывается и сохраняется в возвращаемый `Task`: задача переходит в
      состояние `Faulted`. Вызывающий код получает эту задачу без исключения, поэтому сначала печатается `A`.

      асинхронную реализацию. У `async void` поведение другое: возвращать ошибку некуда, и исключение уходит в
      контекст синхронизации или в пул потоков.

    title: What does a program print when an async method throws before its first await?
    prompt: |
      The `FailAsync` method throws an exception before it reaches any `await`. The method call is outside the
      `try` block, and `await task` is inside it. What does this program print to the console?
    hint: Where does an exception thrown in the body of an `async Task` method go - to the caller, or into the returned task?
    options:
      a: "AB"
      b: An unhandled `InvalidOperationException`, nothing is printed
      c: "A"
      d: An unhandled `AggregateException`
    optionExplanations:
      b: An `async Task` method does not throw at the call site. The compiler catches the exception and stores it in the returned task, so the call `FailAsync(true)` returns normally and `A` is printed.
      c: The exception is not lost. It is stored in the task and thrown again at `await task`, where the `catch` block catches it and prints `B`.
      d: "`await` does not wrap the failure in an `AggregateException`; it throws the task's original exception. That is why `catch (InvalidOperationException)` catches it. The blocking `Wait()` and `Result` are the ones that wrap it in `AggregateException`."
    answer: "AB"
    explanation: |
      The compiler turns the body of an `async` method into a state machine, and any exception inside it, even one
      thrown before the first `await`, is caught and stored in the returned `Task`: the task moves to the `Faulted`
      state. The caller receives that task without any exception, so `A` is printed first.

      The exception surfaces only when the task is awaited. `await task` throws the original
      `InvalidOperationException` (not wrapped in an `AggregateException`), the `catch` block catches it and prints `B`.
      The result is `AB`.

      A practical consequence: argument checks inside an `async` method do not fire at the moment of the call. If the
      error must appear immediately, the check goes into a plain (non-`async`) wrapper method that then calls the
      asynchronous implementation. `async void` behaves differently: there is no task to store the error in, so the
      exception goes to the synchronization context or the thread pool.
