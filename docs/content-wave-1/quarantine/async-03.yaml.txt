      c: "There is no race here: the tasks are completed by explicit `SetResult` calls on one thread, and the order of the array elements is set by the order of the arguments, not by completion time. The result is always the same."
      d: "`string.Join` has a generic overload `Join<T>(string, IEnumerable<T>)`, and `int[]` matches it. So the elements of the array are joined, not the result of calling `ToString()` on the array itself."
    answer: "1,2"
    explanation: |
      `Task.WhenAll` returns a task that completes when all the supplied tasks have completed. Its result is an array that
      holds the results in the same order in which the tasks were passed to `WhenAll`. Completion order does not matter:
      the element at index 0 always comes from the first task and the element at index 1 from the second.

      Here `second.SetResult(2)` runs before `first.SetResult(1)`, but `first.Task` is the first argument, so the array
      is `[1, 2]` and `string.Join` prints `1,2`.

      This is useful in practice: you can start several independent operations at once and then match the results to the
      original requests by index, without caring which operation answered faster.
